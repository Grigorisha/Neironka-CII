# Обработка одиночного кадра — `camera_tools/process_frame.py`

Утилита для обработки отдельных кадров: на вход путь к изображению, на выход —
**одно** обработанное изображение. Что именно окажется на выходе, определяют флаги.

Статус: **реализовано и проверено**. Решения по спорным местам согласованы (см. п. 7).

```bash
python3 camera_tools/process_frame.py --input <кадр> --output <файл.png> <флаг-вывода> [<флаг-пайплайна>]
```

---

## 1. Задействованные модули

| Модуль | Что даёт |
|---|---|
| `yolo_pipeline.py` → `RoadDefectYoloPipeline` | 5 YOLO-моделей: продольная / поперечная / крокодиловая трещина, яма, разметка. Боксы + класс, подавление пересечений и вложенных боксов |
| `yolo_sam_pipeline.py` → `YoloSamMaskPipeline` | бокс от YOLO как промпт для SAM → точная маска дефекта |
| `mask_pipeline.py` → `SamOwlVitMaskPipeline` | OWL-ViT (детекция по текстовому описанию) + SAM. Знаки, столбы, светофоры, люки |
| `camera_tools/process_frame.py` | CLI, объединяющий всё вышеперечисленное |

Константы: цвета и имена повреждений — в `yolo_pipeline.py`
(`MODEL_KEY_COLORS_BGR`, `MODEL_KEY_RU_NAMES`, `color_for_model_key()`);
классы и палитра инфраструктуры — в `mask_pipeline.py`
(`INFRA_TEXTS`, `INFRA_COLORS_BGR`, `INFRA_GROUP_RU_NAMES`, `color_for_infra_label()`).

---

## 2. Группа 1 — что показывать (обязательна, ровно один флаг)

| Флаг | Что на выходе |
|---|---|
| `--boxes-damage` | исходный кадр, поверх — рамки повреждений покрытия (5 YOLO-моделей) |
| `--boxes-infra` | исходный кадр, поверх — рамки знаков, столбов, светофоров, люков |
| `--boxes-all` | исходный кадр, поверх — рамки обоих источников |
| `--masks` | чёрный фон, цветные объекты. Чем заполнять — группа 2 |

---

## 3. Группа 2 — каким пайплайном (только вместе с `--masks`)

Ровно один флаг. Указанный без `--masks` — ошибка с внятным сообщением.

| № | Флаг | Псевдоним | Повреждения (5 моделей) | Инфраструктура |
|---|---|---|---|---|
| 1 | `--pipe1` | `--pipe-seg-all` | точные маски SAM | маски SAM |
| 2 | `--pipe2` | `--pipe-box-all` | заливка бокса | маски SAM |
| 3 | `--pipe3` | `--pipe-seg-damage` | точные маски SAM | — |
| 4 | `--pipe4` | `--pipe-seg-infra` | — | маски SAM |
| 5 | `--pipe5` | `--pipe-box-damage` | заливка бокса | — |
| 6 | `--pipe6` | `--pipe-box-infra` | — | заливка бокса |

Режимы 1-5 — ровно как в исходной постановке. Режим 6 добавлен по итогам обсуждения.

**Эквивалентная явная форма.** Выбор по сути двумерный, поэтому то же самое можно
задать напрямую — удобно, если режимов станет больше:

```bash
--damage {seg,box,off}  --infra {seg,box,off}
```

Например, `--pipe1` ≡ `--damage seg --infra seg`. Смешивать `--pipeN` и
`--damage/--infra` в одном вызове нельзя, комбинация `off`+`off` отвергается.

## 4. Палитра

Цвета фиксированы за классом — один и тот же цвет всегда означает одно и то же,
независимо от кадра и порядка детекций.

**Повреждения покрытия** (`MODEL_KEY_COLORS_BGR`):

| Цвет | Класс |
|---|---|
| красный | яма |
| пурпурный | крокодиловая трещина (сетка) |
| жёлтый | продольная трещина |
| голубой | поперечная трещина |
| зелёный | разметка |

**Инфраструктура** (`INFRA_COLORS_BGR`) — отдельная палитра, намеренно
не пересекающаяся с палитрой повреждений, иначе в совместном режиме объекты
двух пайплайнов не различить:

| Цвет | Группа |
|---|---|
| оранжевый | дорожный знак |
| синий | столб / опора / фонарь |
| фиолетовый | светофор |
| белый | люк / решётка / водоотвод |

---

## 5. Классы инфраструктуры (`INFRA_TEXTS`)

Отдельный от `DEFAULT_TEXTS` список: короче (заметно быстрее прогон OWL-ViT) и
без повреждений покрытия и разметки, которые ищут YOLO-модели.

- **Знаки:** road sign, traffic sign, stop sign, speed limit sign, warning sign
- **Столбы:** lamp post, street light, light pole, pole, utility pole, electric pole, telephone pole
- **Светофоры:** traffic light
- **Люки и водоотвод:** manhole, manhole cover, drain grate, storm drain

Деревья, машины и людей не включал — при необходимости добавляются одной строкой.
Полный `DEFAULT_TEXTS` (~80 классов) остался в модуле для обратной совместимости.

## 6. Прочие параметры

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `--threshold` | порог уверенности YOLO (повреждения) | 0.25 |
| `--infra-threshold` | порог уверенности OWL-ViT (инфраструктура) | 0.15 |
| `--weights-dir` | папка с `.pt` весами YOLO | из `local_config.py` |
| `--device` | `cuda` / `cpu` | автоопределение |
| `--calib` | файл калибровки — устранить дисторсию перед обработкой | не применяется |

Формат вывода — **PNG без потерь**: у JPEG артефакты сжатия «замыливают» границы
масок и тонкие трещины. Если нужен JPEG — меняется одной строкой.

Модели загружаются лениво: в режимах только-повреждения OWL-ViT не поднимается,
в режимах только-инфраструктура не грузятся YOLO-модели.

Если ничего не найдено, изображение всё равно сохраняется (для рамок — чистый
оригинал, для масок — чёрный кадр), код возврата 0. Пустой результат — валидный
результат, а не ошибка.

## 7. Принятые решения по спорным местам

| Вопрос | Решение |
|---|---|
| «Три флага», а описано пять | Описка. Пятёрка верна и полна: выбор двумерный (повреждения `seg`/`box`/`off` × инфраструктура `вкл`/`выкл` = 6 комбинаций минус бессмысленная «ничего»). Реализованы все, плюс шестая по п. ниже |
| Чем рисовать `--boxes-infra` | Рамками поверх оригинала, симметрично `--boxes-damage` |
| Нужен ли `--boxes-all` | Да, добавлен |
| Нужны ли знаки/столбы заливкой боксов | Да, добавлен как `--pipe6` |
| Дубли между пайплайнами | **Оставлены намеренно.** В совместных режимах (1, 2) один объект может быть найден и YOLO, и OWL-ViT — увидим на реальном материале, чистку отложили. Риск снижен тем, что `INFRA_TEXTS` не содержит повреждений и разметки |
| Пять плоских флагов вместо двух параметров | Оставлены как основной вход; параллельно доступна явная форма `--damage/--infra` |
| Палитра инфраструктуры | Заведена отдельная, без пересечений с повреждениями |
| Производительность | Ленивая загрузка моделей + сокращённый `INFRA_TEXTS` |

## 8. Примеры

```bash
# рамки повреждений поверх оригинала
python3 camera_tools/process_frame.py --input frame.png --output out.png --boxes-damage

# рамки знаков и столбов
python3 camera_tools/process_frame.py --input frame.png --output out.png --boxes-infra

# рамки всего сразу
python3 camera_tools/process_frame.py --input frame.png --output out.png --boxes-all

# маски: всё вместе, повреждения сегментированы SAM
python3 camera_tools/process_frame.py --input frame.png --output out.png --masks --pipe1

# маски: только повреждения, закрашенные боксы
python3 camera_tools/process_frame.py --input frame.png --output out.png --masks --pipe5

# то же самое в явной форме
python3 camera_tools/process_frame.py --input frame.png --output out.png --masks --damage box --infra off
```

## 9. Что проверено

- Все четыре флага группы 1 и все шесть режимов группы 2 запускаются и сохраняют результат.
- Валидация: пайплайн без `--masks`, `--masks` без пайплайна, два флага вывода
  одновременно, `off`+`off` — во всех случаях внятная ошибка, а не падение.
- Повреждения: на тестовом кадре стабильно находятся 4 ямы (0.685 / 0.589 / 0.393 / 0.325),
  маски SAM повторяют форму выбоин.
- Инфраструктура: механика пайплайна исправна (при пороге 0.001 выдаёт 397 кандидатов),
  палитра и сегментация SAM отрисовываются корректно.

**Ограничение проверки.** На имеющихся записях нет знаков, фонарей и светофоров —
максимальная оценка OWL-ViT по инфраструктуре около 0.06 при пороге 0.15, то есть
ноль детекций там честный. Качество распознавания инфраструктуры на реальном
материале ещё предстоит оценить, когда появятся подходящие кадры; возможно,
понадобится подобрать `--infra-threshold`.
